# Wishes — Design Context

> Generated by the `teach-impeccable` workflow. Update this file as the product evolves.

## Design Context

### Users
Brazilian users managing wishlists and gift lists. They access the app in personal, low-urgency moments — browsing items they want, sharing lists with friends or family, or checking what someone else wants. The job to be done is: **keep your desires organized and shareable, effortlessly**.

### Brand Personality
**Calm · Generous · Delightful**

The interface should feel like a thoughtful gift — warm but not flashy, organized but not sterile. It earns trust through polish, not noise.

### Aesthetic Direction
- **Dark-first**: The app forces dark mode on the login page and defaults to dark system color scheme. All future screens should honor this.
- **Color palette**: Deep near-black greens (`#080A0B` base) with neon green accent (`#1ED760`) for CTAs and focus states. Muted, earthy neutrals for secondary elements.
- **Typography**: Switzer for display/wordmarks (elegant, geometric), Manrope for UI text (friendly, readable).
- **Motion**: Slow, ambient orbital motion for the background. Snappy, spring-like micro-interactions for user actions (btn press, hover). Never loud.
- **Anti-references**: Avoid e-commerce energy (busy grids, badges, discounts). Avoid social-media anxiety patterns (counters, streaks, urgency).

### Design Principles

1. **Depth over flatness** — Use layered box-shadows and subtle gradients instead of hard borders. The interface should feel like it has physical weight.
2. **Motion earns its place** — Every animation must have a purpose: entrance animations orient the user; micro-interactions confirm intent; ambient motion creates atmosphere. Never animate for decoration alone.
3. **Generous hit areas** — Every interactive element must be at least 44×44px. Extend with padding; never rely on visual bounds.
4. **Concentric border radius** — Nested rounded elements must satisfy `outerRadius = innerRadius + gap`. Mismatched radii destroy the sense of craft.
5. **Respect user preferences** — Always implement `prefers-reduced-motion` to disable or simplify animations. Accessibility is non-negotiable.
